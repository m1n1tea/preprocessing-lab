# Dirty vs Clean GraphRAG Experiment

## Research question

How does preprocessing of technical/scientific PDF documents affect
the quality and topology of a knowledge graph generated by GraphRAG?

## Input documents

1. `data/source/stat3.pdf`
2. `data/source/tanaka1981.pdf`

Both documents concern controlled rolling of steel and related
metallurgical processes.

Each experimental pipeline must construct ONE graph from BOTH documents.

---

## Experiment A: Dirty

Pipeline:

PDF
-> MinerU
-> extracted text
-> GraphRAG
-> Dirty Knowledge Graph

Only unavoidable technical transformations such as UTF-8 serialization
are allowed before GraphRAG.

Do not fix:
- OCR errors
- headers
- line-break hyphenation
- unit formatting
- tables
- formulas
- abbreviations

---

## Experiment B: Clean

Pipeline:

PDF
-> MinerU
-> structural preprocessing
-> cleanup
-> normalization
-> GraphRAG
-> Clean Knowledge Graph

Preprocessing includes:

1. Unicode cleanup
2. repeated headers/footers removal
3. hyphenation repair
4. OCR artifact handling
5. formula protection
6. table protection
7. number/unit preservation
8. unit normalization
9. date normalization
10. abbreviation handling
11. structural validation

---

## Chunking

Initial configuration:

chunk_size: 800 tokens
chunk_overlap: 120 tokens

Dirty and clean must use the same settings.

Avoid splitting:
- formulas
- table rows
- number-unit pairs
- sentences where possible
